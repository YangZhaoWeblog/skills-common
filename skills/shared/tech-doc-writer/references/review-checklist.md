# 技术文档检查表

## 通用

- 只扫标题和视觉中心，能否说清目标、边界和结论？
- 是否以当前文件、当前代码和用户最新确认作为真源？
- 用户纠正的术语、事实、范围和样式是否传播到全文？
- 每节是否只有一个主要视觉中心？
- 图、表、正文是否各自承担不同信息？
- 是否删除了讨论过程、重复解释和无关旧问题？
- 名称性信息是否统一使用 **加粗**，没有行内代码样式？

## 变更设计

- 如存在共同状态或关系模型，是否在前置位置？
- 数据和接口均受影响时，数据结构是否先于接口？
- 新增、修改、重命名、删除、语义调整是否逐项闭合？
- 新增结构和事件载荷是否定义，复用结构是否避免重复？
- 接口表是否覆盖实际受影响的请求、响应、删除项和共享返回字段？
- 时序图是否只画变化流程和关键门禁？
- 如存在跨组边界，受影响方是否能看出自己的动作或待确认项？

## 验证调研

- 开头是否有问题、口径和结论摘要？
- 是否有结果总览矩阵？
- 环境、方法、数据、限制是否足以支撑结论？
- 实测、引用和推断是否区分？
- 未测和失败场景是否明确？
- 是否一眼看出改什么、不改什么、为什么？
