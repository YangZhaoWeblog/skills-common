# 当前成品真源与正文完整性

## 核心原则

**当前成品服务当前任务和已确认范围。** 不为说明改过什么而补回用户删除的对象或编辑旁白。当前判断所需的真实对比、历史证据，以及用户要求的变更文档或记录应保留，明确事实来源和时间范围；不得借此恢复用户明确要求排除的内容。

## 正向 Schema

按段落职责检查信息贡献，不把全部句子套成动作链：

| 职责 | 正向 Schema | 示例 |
| --- | --- | --- |
| 定义 | 对象 → 含义或边界 | 任务是具有明确完成条件的工作单元。 |
| 证据 | 来源/条件 → 观察结果 → 支持范围 | 本次样本中 A 的失败率更低；结论限于该测试环境。 |
| 判断/行动 | 对象 → 判断依据 → 选择或动作 | 任务太多时，先确定优先级，再安排执行。 |
| 必要对比/变更 | 可核查的差异 → 当前意义 | 本次接口将同步返回改为异步通知，调用方需处理回调。 |

写入前检查：这段是否帮助读者理解对象、核查证据或形成判断？定义与证据无需各自附带动作；仅因没有动作而删除，会破坏正文完整性。

## 负向 Schema

| 失败模式 | 典型形态 | 处理方式 |
| --- | --- | --- |
| **历史残留** | “四象限只是处理方式；本页最终……”但本节尚未讨论四象限 | 删除历史对象，直接写当前主张 |
| **编辑过程泄漏** | “原来……后来改成……现在……”，仅描述写稿过程 | 删除无关旁白；真实必要对比或用户要求的变更记录保留 |
| **替代说明残留** | “不是 A，而是 B”，但 A 不是读者当前需要区分的对象 | 删除 A，只写 B 的当前判断 |
| **范围污染** | 为了说明某概念不重要，先把它引入标题或开头 | 不引入该概念；把边界放到真正需要它的章节 |
| **旧标题回声** | 正文无关地继续解释已删章节名、旧术语或旧分类 | 删除回声；不能仅因改过标题就删除仍必要的定义与事实 |
| **删改旁白** | “这里不再讨论……”“前面删除了……” | 从正文删除；必要的变更记录留在工作记录或 Git diff |

## 删除测试

每次删掉或替换一个概念后，检查三件事：

1. 删除该概念后，是否损失必要定义、证据或对比？只留下无关编辑痕迹时不补回。
2. 读者只看当前标题和正文，是否会误以为该概念仍属于本文主线？会就继续删。
3. 本段是否仍服务当前任务，且没有把历史事实误写为当前状态？不要求每段同时具有判断和动作。

**不要为了证明删除发生过，而在成品里留下删除痕迹。**
