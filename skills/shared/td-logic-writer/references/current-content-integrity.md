# 当前成品真源与正文完整性

## 核心原则

**当前成品只写当前系统。** 旧稿、删掉的概念、被否定的标题和编辑过程只用于理解变更，不进入正文。用户要求删除某个对象后，正文应像它从未属于当前方案一样自然；不要留下“以前是 A、现在改成 B”的说明。

## 正向 Schema

正文句子优先使用：

> **当前对象 → 当前判断 → 当前条件/证据 → 当前动作或边界**

例如：

> 任务太多时，先决定哪些事情值得占用当前执行容量，再安排具体处理方式。

写入前逐句问：这句话现在在处理哪个对象？它给出什么当前判断？它改变什么动作？三项答不出一项，就删除、合并或移到正文外。

## 负向 Schema

| 失败模式 | 典型形态 | 处理方式 |
| --- | --- | --- |
| **历史残留** | “四象限只是处理方式；本页最终……”但本节尚未讨论四象限 | 删除历史对象，直接写当前主张 |
| **编辑过程泄漏** | “原来……后来改成……现在……” | 删除整个变更叙述，只保留最终内容 |
| **替代说明残留** | “不是 A，而是 B”，但 A 不是读者当前需要区分的对象 | 删除 A，只写 B 的当前判断 |
| **范围污染** | 为了说明某概念不重要，先把它引入标题或开头 | 不引入该概念；把边界放到真正需要它的章节 |
| **旧标题回声** | 正文继续解释已经删掉的章节名、旧术语或旧分类 | 按当前标题链重写，不保留回声 |
| **删改旁白** | “这里不再讨论……”“前面删除了……” | 从正文删除；必要的变更记录留在工作记录或 Git diff |

## 删除测试

每次删掉或替换一个概念后，检查三件事：

1. 删除该概念后，当前句子是否仍然成立？成立就不补回解释。
2. 读者只看当前标题和正文，是否会误以为该概念仍属于本文主线？会就继续删。
3. 本段是否只剩当前对象、当前判断和当前动作？不是就回到骨架。

**不要为了证明删除发生过，而在成品里留下删除痕迹。**
