# 文章推进模式

文章质量不只取决于章节数量和信息密度，还取决于作者如何安排信息，让读者从起点状态走到终点判断。**主推进模式描述章节的组织关系，可以是阅读依赖、对象分类、比较、推导或验证，不限于因果关系。**

按任务选择合适的组织方式，下列四种模式可供参考，不是穷尽分类。每节应有明确职责；定义、同层分类和证据可以并列，只要共同服务主问题，不必让后一节由前一节推出。

## 四种模式

| 模式 | 适用任务 | 读者状态变化 | 最小逻辑 |
| --- | --- | --- | --- |
| **收窄选择空间** | 机会判断、投资研究、职业选择、复杂议题 | 候选越来越少，默认方向越来越明确 | 候选 → 排除 → 筛选 → 排序 → 入场/停止 |
| **根原则推导系统** | 多项规则确由共同原则推出的个人系统或决策文档 | 从问题得到原则，再得到规则和边界 | 问题 → 根原则 → 判断对象 → 规则/反馈；涉及稀缺资源或持续承诺时补容量边界 |
| **逐层建立理解** | 技术解释、概念教学、面向非专业读者的科普 | 每一步只增加下一步所需的复杂度 | 直觉问题 → 最小模型 → 机制 → 应用/边界 |
| **案例验证判断** | 经验总结、投资复盘、管理方法、行为判断 | 抽象判断被案例证明、修正或转成自检 | 反直觉判断 → 案例 → 证明任务 → 可迁移规则 |

## 模式怎么用

写骨架时不要只写“本篇使用收窄模式”，而要写出以下六项：

1. **起点问题：** 读者现在不知道什么，或误判了什么？
2. **终点判断：** 读者最后应该能做什么选择、解释或动作？
3. **章节关系：** 哪些章节有阅读依赖，哪些是在同一对象或维度下并列？为何这样排序？
4. **状态变化：** 每节结束时，读者少了什么候选、解决了什么疑问或获得了什么判断？
5. **证据任务：** 每个例子、数据、图表或故事究竟证明什么？
6. **失败对照：** 如果打乱顺序、混用层级或删去某节，会损失什么理解或判断？

如果写不出第 3、4 项，先检查章节职责与组织依据；不为制造递进而添加因果关系。

## 案例一：收窄选择空间

**样本：**《AI for Science 详细介绍（下）：机会与入场》

**起点问题：** 普通人或小团队在 AI for Science 还有没有位置？如果有，应该从哪里进入？

**推进链：**

1. 造神层需要名人堂团队和数亿美元，先排除。
2. 科学基础模型和自驾实验室需要重数据、重算力或重资产，继续排除。
3. 工具与编排部分可做，但通用层竞争激烈，缩小到领域特定接口。
4. 评估、验证、复现更依赖学科判断，保留为小团队优势所在。
5. 用“模型强弱还是学科判断”建立筛选器，给后面的机会分类提供共同标准。
6. 从机会菜单中再排序出 verifier、实验设计和假科学检测等切口。
7. 最后给出从基准论文到事实标准的入场路径。

**读者状态变化：** 从“整个行业都可能是机会”，变成“避开重资产和模型规模竞争，优先验证吃学科判断的基础设施切口”。

**失败对照：** 直接并列介绍六类基础设施，最后突然宣布三类最值得做。这样读者必须自己完成排除和排序，文章只是资料菜单。

**迁移条件：** 候选较多、资源有限、需要回答“先看哪里”时使用。没有真实候选或没有排除依据时，不要强行使用。

## 案例二：根原则推导系统

**样本：**《Anki 卡片系统》

**起点问题：** 卡片积压和每日复习负担为什么会发生，今后什么知识值得进入 Anki？

**推进链：**

1. 先指出过量制卡会消耗未来注意力。
2. 提出根原则：Anki 是用未来注意力购买检索能力。
3. 由此推出准入门槛：预期损失必须大于制卡与维护成本。
4. 再划分 Anki、Obsidian 和原文的知识分工。
5. 用复习反馈处理慢卡、低价值卡和阶段性卡片。
6. 最后用注意力预算和 FSRS 预测负载限制新增量。

**读者状态变化：** 从“卡片越多越安心”，变成“每张卡都是未来负债，必须服从注意力预算”。

**失败对照：** 分别列制卡规则、复习规则、暂停规则和维护规则，却不解释它们为什么统一服从注意力预算。读者只能记零散规定，遇到新卡仍不会判断。

**迁移条件：** 规则需要长期运行、多个操作都应由同一原则推出时使用。核心原则无法解释大多数规则时，说明原则还不够根本。

## 案例三：价值冲突转成取舍规则

**样本：**《财富、工作与自由》

**起点问题：** 财富、工作、关系、健康和探索发生冲突时，应该牺牲哪一边？

**推进链：**

1. 先定义目标不是遥远退休数字，而是逐步赎回时间。
2. 把财富重新定义为未来选择权，而不是资产数字本身。
3. 把自由拆成积累期、选择期和完全独立期，避免只有“退休/未退休”二元判断。
4. 用最小遗憾图同时保留未来选择权与不可逆人生体验。
5. 把价值冲突压成可调用规则：重大处慢、可逆处快；不赌命；不为预测中的日期错过已确认的关系。
6. 最后允许真实新事实改变长期路径。

**读者状态变化：** 从“必须在财富和生活之间二选一”，变成“用选择权、可逆性和遗憾成本处理具体冲突”。

**失败对照：** 分别讨论工作、投资、婚姻、健康和兴趣，最后用一句“保持平衡”收尾。主题看似完整，遇到具体冲突仍没有判断句。

**迁移条件：** 议题包含多个长期价值，不能靠单一目标排序时使用。规则必须能在冲突现场直接调用，不能只停留在价值宣言。

## 案例四：案例验证判断

**样本：**《李录：投资，是一种可以只靠脑子……》

**起点问题：** 价值投资到底难在哪里？知道原则的人，为什么仍可能在关键时刻做不到？

**推进链：**

1. 先用“5% 的价值投资者”打掉“我懂所以我能做到”的直觉。
2. 用群体本能和独处、不作为的耐受度解释为什么执行困难。
3. 用 Timberland 案例展示：发现便宜、调查红旗、判断管理层、走进门店。
4. 用七倍回报说明等待不是被动，而是建立在安全边际和基本面改善上。
5. 用错失机会说明“不行动”也是机会风险。
6. 用 Bloomberg 和大机会章节扩展到卖出、机会成本和长期准备。
7. 最后把抽象原则转成三个留给读者的自检问题。

**读者状态变化：** 从“价值投资是知识或术语”，变成“它是一套需要调查、承受孤独、等待并在优势存在时行动的行为要求”。

**失败对照：** 先列五条价值投资原则，再用多个故事装饰。故事之间没有不同证明任务，读者记住了人物和回报，却没有学到判断过程。

**迁移条件：** 抽象原则难以相信、需要展示真实判断过程或需要把原则转成自检时使用。每个案例必须承担不同证明任务；重复证明同一件事时删掉弱案例。

## 案例五：逐层建立理解

**样本：**《ChatGPT 的原理、咒语和应用》

**起点问题：** 非专业读者想知道 ChatGPT 怎么工作，但完整数学和工程细节会让其无法进入。

**推进链：**

1. 先给最小直觉：根据已有文本逐词预测下一个词。
2. 读者追问概率从哪里来，再引入文本统计和词语组合。
3. 组合空间爆炸后，引入模型，说明模型如何用少量实验概括大量情况。
4. 再从模型过渡到神经网络、参数、损失函数和梯度下降。
5. 到复杂度超过目标读者所需时主动收束，保留“基本概念足够简单”的锚点。
6. 从原理自然转入 Prompt，再落到翻译、知识库和插件等应用。

**读者状态变化：** 从“ChatGPT 像魔法”，变成“它先建立可用的生成直觉，再逐步增加机制，并知道哪些细节暂时不必理解”。

**失败对照：** 一开始直接讲 Transformer、Embedding、Attention 和训练流程，再在结尾补几个应用。读者还没建立问题框架，就被术语挡在门外。

**迁移条件：** 读者需要从零理解复杂机制，且完整细节会超过当前学习目标时使用。每引入一个概念，都要回答它解决了前一步的什么疑问。

## 交付前检查

- 能否说出文章的起点问题和终点判断？
- 能否说明章节之间的依赖或并列关系及排序依据？
- 每节是否真的改变了读者状态？
- 案例、表格和图是否承担明确的证明或结构任务？
- 是否为了套推进模式而把必要的并列分类、定义或证据删除，或虚构了因果关系？

这些样本是**可拆解的结构案例**，不是标题模板。不得为了模仿样本而增加背景、案例、章节或总结。
