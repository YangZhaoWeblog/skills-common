# Writing Workflow

## 1. 先定文章契约

先读当前文、用户修改、截图、链接和参考样本。真源优先级通常是：用户刚确认的成品 / 当前文件 > 旧版本 > 历史讨论。

写作前在内部回答：

- 读者是谁，真正要做什么判断？
- 需要建立什么定义、关系或默认选择？哪些事实会改变判断？
- 哪些内容不属于本文，应该链接、留在来源或另写？

先按 [current-content-integrity.md](current-content-integrity.md) 明确使用情境与解释量。决策文可先探讨本质再形成选择；解释型博文先明确要解释的问题与关系，不必预设默认选择。

长任务维护最小纠正记录：

| 纠正对象 | 已确认写法 | 影响范围 |
| --- | --- | --- |
| 术语 / 事实 / 范围 / 风格 / 流程 | 新约束 | 必须同步的章节或产物 |

这张表用于写作记忆，不默认进入正文。

## 2. 按任务选骨架

| 类型 | 检查路径（不是固定目录） |
| --- | --- |
| 概念边界 | 根定义 → 边界与混淆对象 → 区别改变什么使用判断 |
| 项目认知 | 负责什么 → 关键关系与边界 → 日常判断与自检 |
| 判断标准 | 判断对象 → 条件与反例 → 采取什么动作 |
| 证据型决策 | 默认选择 → 改变选择的条件 → 候选矩阵 → 执行 / 停止条件 → 来源 |

骨架服务阅读任务，可按推导、比较、逐层理解、案例验证或并列查阅组织，不固定选用上表的顺序。先定义后使用，有依赖再排序，必要的同层分类可并列；不强制背景先行，也不为了完整感补齐所有章节。标题选型见 [style-rules.md](style-rules.md)，组织关系见 [progression-modes.md](progression-modes.md)。

## 3. 建立判断账本

承担判断、选择或行动任务的证据型决策、重写或复杂文章，先在内部维护下表。解释型文章按需要记录核心概念、机制关系、证据与适用边界，不强求行动结论或改变选择的条件：

| 关键判断 | 主载体 | 改变选择的条件 | 必要证据 | 正文外归属 |
| --- | --- | --- | --- | --- |
| 一条可行动结论 | 开场 / 表格 / 行动门禁之一 | 何时例外 | 一条最短证据链 | 来源、附录或关联笔记 |

- 一条判断只能有一个主载体。
- 同一判断在其他位置出现，仅保留当前理解或使用必需的条件、例外、证据或动作，并通过删除检验。
- 有明确主笔记且读者可跳转时，通用规则只由主笔记承担；其他文章链接它，只保留本篇不可缺的最短提醒。

## 4. 先选读者任务，再放置信息

在骨架旁为每节标注：**读者要理解、查阅、判断或执行什么 → 主载体**。

| 读者任务 | 首选载体 |
| --- | --- |
| 多个同类对象间横向比较 | 表格；仅当对象、列和判断维度稳定，且读者需要左右扫读 |
| 按先后执行或理解时间顺序 | 编号步骤或流程图 |
| 记住规则、门槛或默认动作 | 短段或清单 |
| 分清概念、类别或边界 | 对象标题 + 定义或关系说明 |
| 理解关系、层级、流向或映射 | 图 |

表格是横向比较工具，不是压缩工具。若没有多个同类对象、共同维度或横向扫读需求，就不要把规则、步骤、单一对象说明或概念解释切成网格；单元格已装进完整段落时，也应改回文字、清单或图。

| 信息 | 首选位置 |
| --- | --- |
| 默认选择、边界、后果 | 开场短段或章节中心句 |
| 候选比较、排序、变更映射 | 表格；前提是存在稳定共同维度 |
| 准入门槛、执行动作 | 短段、清单或步骤 |
| 层级、关系、流程、映射 | 图 |
| 改变选择的关键证据 | 判断旁的最小充分解释，附来源 |
| 不改变结论的样本细节、注册信息、长争论、历史问答 | 来源、附录或关联笔记 |

图或表已经表达的信息不逐项复述；正文保留必要定义、证据、理由、例外和后果。没有稳定比较维度时，不用表；没有空间关系时，不用图。

保留事实不等于保留原句。对每条事实判断它属于：

- **决定性证据**：会改变候选、门槛或停止条件，留在判断旁。
- **可追溯细节**：支撑来源但不改变选择，留在表格注释或来源说明。
- **背景记录**：留在附录或关联笔记。

两个以上并列段落若导向同一动作，先判断读者是否需要横向比较；需要才合成决策矩阵，否则合并为清单或判断段。表格形成后删掉逐项复述。压缩时保留证据的范围与力度，不能把“本次纳入”“某研究”扩大成“全部现有”，也不能把“不能支持”写强成“证明”或“排除”。

## 5. 无损压缩

按以下顺序重写：

1. 先通读话题与使用场景的切换：是否仍服务同一问题，必要转换是否有依赖或明确分区；先修组织，不只缩句。
2. 标记段落职责，把重复判断合并到主载体；需要逐项执行或横向查阅时保留清单、表格。
3. 按 [current-content-integrity.md](current-content-integrity.md) 的最小充分解释与删除检验，逐句确认具体损失；没有明确损失就删，有追溯价值但当前不需要的移旁路。
4. 用共性判据替代穷举，用必要关系替代抽象换述；例子、反例、总结仅补具体缺口，理解已成立就停。
5. 表、图或可用链接已充分承载的信息可去重；必要因果、事实、前提与边界留在读者需要处。

对“精炼、去重、重写”任务，结束前在内部核对：每条关键判断原来有哪些载体，现已合并、移位或删除了什么。若只调整标题和语序，说明压缩尚未发生。

不设字数或句数硬限；复杂推导讲到足够理解。解释判断所必需的证据保留在判断旁，不能为压短正文移走。

## 6. 事实与主观边界

- 按 [current-content-integrity.md](current-content-integrity.md) 的规则依据检查逻辑漏洞：保留事实与用户选择，质疑判据时先指出问题并提出修正，不暗改价值和数值。
- 技术 / 项目事实：验证现行代码、协议、数据、配置和当前文档，区分旧事实与现状。
- 健康 / 医美 / 财务：标明来源、不确定性和个人约束，不装成专业诊断。
- 情感 / 人生：区分外部观点、事实观察和个人策略。
- 影响核心判断但无法验证的内容，先停下来查或问；不影响骨架的内容标为假设或待验证。

## 7. 用成品反哺

- 正向样本：用户或评审最终认可的结构和载体。
- 负向样本：用户删掉、压缩或明确反对的内容，识别“看似完整但降低判断速度”的模式。

只把跨主题规律写回 Skill；一次性事实和偏好留在项目记录。
