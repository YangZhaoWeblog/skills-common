# Writing Workflow

## 1. 判断文章任务

先判断文章到底要干什么：

- 分清概念边界。
- 建立判断标准。
- 把调研压成决策。
- 把项目经验压成负责人的认知框架。
- 把个人经验压成未来可复用的策略。

如果只是定义概念、组织知识地图、生成学习材料或写正式文档，停止使用本 skill，转交更合适的链路。

## 2. 审稿，不急着改句子

先读用户原文、截图、链接、旧版本和用户修改。审这些问题：

- 读者阅读前最混乱的点是什么？
- 哪个根概念还没定义？
- 哪些事实必须先出现？
- 哪个章节承担了两个以上任务？
- 只看页面形状，是否像正确材料拼接，而不是有设计过阅读路径？
- 每个大节有没有视觉中心？如果没有，读者第一眼该看哪里？
- 哪句话只是 AI 会写、但人不会保留？
- 哪个关系更适合画图？
- 哪个表格只是把段落换成网格，并没有提高判断速度？
- 用户哪句原话比生成版本更有生命力？

## 3. 搭标题链

默认顺序：

1. 交代背景或混乱。
2. 定义根概念，不先讲 ID、字段、规则。
3. 分清核心对象和边界。
4. 展示关系、映射、排序或判断标准。
5. 说明系统或个人策略如何使用这套关系。
6. 点出常见误区、止损点或下一步行动。

这只是默认骨架，不是模板。每篇文章按真实认知路径删改。

## 4. 选择载体

- 判断、取舍、后果：用文字。
- 稳定对比、自检标准、排序、动作门禁：必要时用表格。
- 层级、映射、流向、权限、坐标系：用图。
- 同级短项：用 bullet list。

不要把关系式写成正文装饰。如果关系需要被“看见”，放进图里。

写表格前先问：没有这个表，读者是否真的更难判断？如果答案是否，表格会制造假清晰。

Owner 地图、项目认知图这类文章，不要急着写完整解释文。每节先建立挂载面：中心判断 / 图表 / 自检问题；等局部学透后再扩写。

## 5. 重写顺序

1. 删除只为格式存在的段落和标题。
2. 调整章节顺序，让标题链成立。
3. 先定每个大节的视觉中心，再写段落。
4. 把背景压到足够支撑下一节为止。
5. 把泛泛解释改成边界、映射、风险、使用后果。
6. 删掉被中心图 / 表 / 列表吸收的重复文字。
7. 保留用户准确的人话。
8. 把图放到读者正需要它的位置。
9. 最后修标题、分隔线、编号和术语样式。

## 6. 事实与主观边界

- 技术/项目文：验证现行代码、proto、DB、配置、旧文档；区分旧文档和当前实现。
- 健康/医美/财务类：标清来源、不确定性、个人约束；不装成专业诊断。
- 情感/人生判断：区分外部观点、事实观察、我的策略。
- 无法验证但不影响骨架的内容，标为假设或待验证；影响核心判断的内容，先停下来查或问。
