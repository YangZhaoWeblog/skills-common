# Style Rules

## 元规则

文章的核心不是“解释得完整”，而是把混乱材料压缩成未来可复用的判断系统。

保留服务主问题的定义、关系、判断、条件、证据、例外和动作；无信息贡献的重复内容才删掉、并入或移到旁路。

## 标题链

- 标题是文章逻辑，不是装饰。
- 标题要按“读者下一步必须分清什么”排列；中文线性长文、判断文章和项目认知文章的一级标题默认使用 `一、二、三、四` 编号。
- 按对象关系和阅读依赖排序；同级标题保持相称的抽象层级，必要的并列分类不必改成因果链。
- 标题层级连续；没有父章节时，不直接使用更深一级标题。
- 定义/决策型标题用准确、精练、对象明确的词组；故事型可用口语或悬念，操作手册可用动作。
- 文件名已经是文章题目时，正文从一级标题开始，不重复写总标题。非线性内容、短笔记、局部小改、已有稳定格式或用户明确保留原样时，不为了整齐重排标题。
- 文件名必须覆盖全文真正处理的对象和范围；若文章从单一分类器扩展到容量、精力、工具或执行，应重新命名文章身份，而不是继续沿用局部名称。
- 文件名说明全文对象与范围，标题链呈现结构，加粗呈现关键判断；只扫标题可看清组织，只扫标题与加粗可抓住主线。
- 标题不必复述结论，不设字数硬限；以对象准确、层级一致、逻辑排序为准，避免含混标签和冗长摘要。
- 精练不能删除影响正确理解的限定；操作标题中的执行前提或放行条件必须明确，例如“验证通过后开放流量”，不能缩成“验证并开放流量”。
- 不默认设置“一句话结论”章节。个人知识文章可以有开场短段，但不要套正式文档的结论先行格式。
- 一级标题超过 8 个时检查范围、重复与导航负担，不以数量直接判定需要删节或拆文。

### 标题正反 Schema

| 语境 | 正向 | 反向及原因 |
| --- | --- | --- |
| 定义/决策型结构 | 时间管理的本质 → 任务的定义 → 任务的优先级 → 执行安排 | 先想清楚 → 再分一分 → 开始行动：对象含混；为动作链牺牲结构 |
| 对象与层级 | 本地身份 → 空间身份；各节展开对应角色与关系 | 用户 → 空间身份 → SID 字段：同级混用实例、分类与字段 |
| 标题与判断分工 | 标题“任务的优先级”，正文加粗实际排序依据 | 把完整排序结论与全部条件塞进标题：标题变成摘要 |
| 故事型 | “他为什么没有卖出”：正文确有对应事件与悬念 | 把悬念强加到定义文，遮蔽对象 |
| 操作手册 | 检查备份 → 执行迁移 → 验证结果 | 为了使用名词标题，隐藏实际操作顺序 |

示例只展示各自语境下的结构与表达，不是通用标题模板；不要求其他文章使用时间管理的对象或顺序。

## 语言

- 开场形式服从任务：概念文可先给混乱或根定义；决策文先给默认选择和改变它的条件。
- 短段落，每段只做一件事。
- 保留用户准确的人话，不把它改成安全但无味的 AI 书面语。
- 定义读者理解后文所需的概念；删去对目标读者已明确且不影响理解的赘述。
- 少用“体系、机制、能力、赋能、维度”等抽象词，除非它们真的在承担结构。
- 不写模板过渡句，例如“综上所述”“值得注意的是”“本文将从以下几个方面展开”。
- 不把“一句话结论”“核心摘要”“总结”当成默认小节名。
- 不把文章写成百科、SOP、培训材料或公众号总结。
- 同一结论不要用“不是 / 不等于 / 不能”连续换句式重述；真实概念辨析与必要对比按信息贡献保留，不限为一句。
- 精简不能扩大事实强度：保留“本次证据”“某研究”“已核实范围”等限定词，也保留“不能支持”“初步”“可能”等不确定性。

## 视觉中心

- 每个大节先确定一个视觉中心，再写段落。视觉中心可以是核心判断句、流程图、关系图、门禁短列表；没有中心就先重构，不要继续堆文字。
- 视觉中心必须回答本节最重要的问题。读者只看中心内容，也应知道本节在判断什么。
- 视觉中心不必强制是结论句。定义节可以用结构定义，比较节可以用表格，流程节可以用步骤或图；载体服从本节问题。
- 中心内容承担答案后，正文补必要定义、证据、理由、例外或后果；不要把中心内容逐行翻译一遍。
- 二级标题不是越多越清楚。小标题要形成扫描路径；如果只是把碎片分段，就合并或改成中心表 / 图。
- 二级块之间割裂时，用分隔线缓冲；紧密连续解释不要滥用。
- 一级标题已有中文编号时，可用 **2.1 / 2.2** 这类编号增强局部扫描路径，尤其是长节展开。

## 加粗样式

- 加粗承担第二阅读路径：读者只扫标题和加粗内容，也应能复述文章主线。
- 概念、字段、命令、路径、枚举值、文章级判断、默认选择、边界条件、反直觉结论和行动门槛可以加粗。
- 加粗要克制：每个小节优先保留 1–2 个加粗锚点，避免整段加粗、连续多句加粗或泛泛强调。
- 只有可执行代码使用代码块；不使用行内代码样式。
- 英文或 ID 加粗后与中文保留自然空格。

## 图文分工

- 文字承载：判断、边界、例外、后果、取舍。
- 表格承载：稳定维度上的比较、排序、映射，或确实需要并列扫描的自检。
- 图承载：关系、层级、流向、映射、权限边界、坐标系。
- 图能表达的关系，正文要删或压成一行锚点。
- 不为图片单独起无意义标题；如果标题下面只有图，通常不需要标题。
- 大章节之间可用分隔线缓冲阅读节奏；紧密连续解释内部不要滥用。
- 表格不是默认清晰。先问：是否有多个同类对象、共同列和横向扫读需求？三者缺一，就不用表。
- 规则、步骤、单一对象说明和概念解释默认不用表；分别改成短段/清单、编号步骤、短段或小标题。
- 单元格应是短判断或可扫读信息；如果装进完整段落，删表，改回短段、列表或图。

## 反模式

- 看起来正确，但套到任何文章都成立。
- 中央概念还没定义，就开始讲 ID、字段、规则。
- 用表格掩盖弱思考：左列泛泛，右列全是空话。
- 为了显得整齐而使用表格，读者看完仍不知道先看哪里。
- 标题整齐但对象、层级或排序不清。
- 没有视觉中心：标题、段落、表格、列表都正确，但页面像拼装件。
- 小标题很多，但只是在切碎材料，没有形成阅读路径。
- 名称到处加灰底，页面发硬；统一用加粗。
- 图像 PPT 截图：重复标题、画布过大、颜色抢眼、信息少。
- 解释了概念，却没说这个区别改变什么判断或行动。
- 把“被用户删掉的内容”换个说法重新加回来，没有把修改行为当成负向样本。
- 把历史讨论全部塞进正文，用信息量掩盖主线不清。
- 同一判断同时出现在开场、表格、段落和结尾，却没有新增信息。
- 声称“已压缩”，实际只改标题、顺序或措辞，重复载体仍全部存在。
