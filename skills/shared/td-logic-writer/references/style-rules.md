# Style Rules

## 元规则

文章的核心不是“解释得完整”，而是把混乱材料压缩成未来可复用的判断系统。

如果一段话不能帮助读者判断、选择、负责、止损，就删掉或并入别处。

## 标题链

- 标题是文章逻辑，不是装饰。
- 标题要按“读者下一步必须分清什么”排列。
- 后一节应依赖前一节的信息；如果只是并列罗列，重新排序。
- 标题用朴素、准确、可搜索的名词和关系，不用聪明话、口号、诊断腔。
- 文件名已经是文章题目时，正文从一级标题开始，不重复写总标题。
- 不默认设置“一句话结论”章节。个人知识文章可以有开场短段，但不要套正式文档的结论先行格式。
- 一级标题最多 8 个。超过时先压缩范围，而不是继续加节。

好标题倾向：

- 本地身份：租户、用户、角色
- 空间身份：空间、组织、组织角色
- 鉴权怎么用 SID + OrgID
- 先治病，再优化

坏标题倾向：

- 一图看懂关系
- 核心机制解析
- 项目全景认知
- 从混乱到清晰

## 语言

- 背景为先，但不强制结论先行。先交代混乱、边界或判断压力。
- 短段落，每段只做一件事。
- 保留用户准确的人话，不把它改成安全但无味的 AI 书面语。
- 不解释明显词汇，只解释它如何影响边界、权限、风险、排序或行动。
- 少用“体系、机制、能力、赋能、维度”等抽象词，除非它们真的在承担结构。
- 不写模板过渡句，例如“综上所述”“值得注意的是”“本文将从以下几个方面展开”。
- 不把“一句话结论”“核心摘要”“总结”当成默认小节名。
- 不把文章写成百科、SOP、培训材料或公众号总结。

## 视觉中心

- 每个大节先确定一个视觉中心，再写段落。视觉中心可以是核心判断句、流程图、关系图、门禁表、短列表；没有中心就先重构，不要继续堆文字。
- 视觉中心必须回答本节最重要的问题。读者只看中心内容，也应知道本节在判断什么。
- 视觉中心不必强制是结论句。定义节可以用结构定义，比较节可以用表格，流程节可以用图；载体服从本节问题。
- 二级标题不是越多越清楚。小标题要形成扫描路径；如果只是把碎片分段，就合并或改成中心表 / 图。
- 二级块之间割裂时，用分隔线缓冲；紧密连续解释不要滥用。
- 可用 **2.1 / 2.2** 这类编号增强扫描路径，尤其是长节局部展开。

## 名称样式

- 概念、字段、命令、路径、枚举值和文章级判断统一用加粗。
- 只有可执行代码使用代码块；不使用行内代码样式。
- 英文或 ID 加粗后与中文保留自然空格。

## 图文分工

- 文字承载：判断、边界、例外、后果、取舍。
- 表格承载：稳定维度上的比较、排序、自检、动作门禁。
- 图承载：关系、层级、流向、映射、权限边界、坐标系。
- 图能表达的关系，正文要删或压成一行锚点。
- 不为图片单独起无意义标题；如果标题下面只有图，通常不需要标题。
- 大章节之间可用分隔线缓冲阅读节奏；紧密连续解释内部不要滥用。
- 表格不是默认清晰。只有存在稳定比较维度、读者需要横向对照、或动作门禁需要快速扫描时才用表格。
- 如果表格只是把段落拆成网格，删表，改回短段或列表。

## 反模式

- 看起来正确，但套到任何文章都成立。
- 中央概念还没定义，就开始讲 ID、字段、规则。
- 用表格掩盖弱思考：左列泛泛，右列全是空话。
- 为了显得整齐而使用表格，读者看完仍不知道先看哪里。
- 标题整齐但没有递进。
- 没有视觉中心：标题、段落、表格、列表都正确，但页面像拼装件。
- 小标题很多，但只是在切碎材料，没有形成阅读路径。
- 名称到处加灰底，页面发硬；统一用加粗。
- 图像 PPT 截图：重复标题、画布过大、颜色抢眼、信息少。
- 解释了概念，却没说这个区别改变什么判断或行动。
- 把“被用户删掉的内容”换个说法重新加回来，没有把修改行为当成负向样本。
- 把历史讨论全部塞进正文，用信息量掩盖主线不清。
